# Local UI API contract

Base URL: http://127.0.0.1:8765 . All JSON is UTF-8. Errors: non-2xx plus {error: human-readable-string}; validation errors use 400. No authentication needed on loopback; server must reject non-local Host/Origin on mutations.

Config fields:
```json
{"players":[{"name":"BTN","stack":15,"range":"all"},{"name":"SB","stack":12,"range":"all"},{"name":"BB","stack":10,"range":"all"}],"small_blind":0.5,"big_blind":1,"ante":0,"open_sizes":[2.5],"reraise_multipliers":[3],"max_raises":2,"utility":"chips","payouts":[50,30,20],"iterations":1000,"seed":42}
```
Stack/blind/ante units are big blinds (BB), stack INCLUDES forced bets. For >=3 seats, last two players are SB/BB and first player acts first. HU order is BTN/SB then BB. Payouts are decreasing prizes; money units arbitrary but internally consistent. chips versus icm determines utility.

- GET /api/meta → {default_config, hand_labels:[169 strings, row-major AKQJT98765432], model:{title,continuation,limitations:[strings]}, evidence:[{title,url,note}]}
- POST /api/tree body {config,path:[]} → node described below. Builds/explores configuration without solving.
- POST /api/jobs body {config} → job status object. One active solver job at a time, conflict 409. Returns quickly; computation in background.
- GET /api/jobs → {jobs:[job status]}
- GET /api/jobs/{id} → job status object {id,status:"running"|"cancelling"|"completed"|"cancelled"|"failed",config,progress:{iteration,total,...},elapsed_seconds,error:null|string,summary:null|object}
- POST /api/jobs/{id}/cancel body {} → job status. Preserve partial results if available. Do not declare cancelled until worker ends.
- GET /api/jobs/{id}/node?path=<URL-encoded JSON array> → node plus strategy (null until available).
- GET /api/jobs/{id}/export → downloadable JSON result (native mode exports root and summary, with local full-checkpoint paths).
- POST /api/icm body {stacks:[numbers],payouts:[numbers]} → {equities:[numbers]}

Resource-budget stops map to job.status="failed", summary.status="resource_limit" with a visible error message. Available partial nodes and export remain accessible when summary is present. Final progress.iteration equals summary.iterations_completed, including cancellation/resource stops between progress intervals.

Node: {id,path:[action ids],actor:int|null,actor_name:string|null,pot,current_bet,contributions:[numbers],remaining:[numbers],folded:[bool],all_in:[bool],terminal:bool,actions:[{id,label,kind,amount}],strategy:null|{path,actor,actions,visits,hands:{AA:{frequencies:[numbers matching action order],visits,...}}}}.

Frequencies sum to one per trained hand. Absent hand = untrained. Display sample counts; never fill absent hands with invented strategy. Action IDs opaque; retain from API. Tree navigation appends an ID and re-requests node. Terminal nodes have no actor/actions. Use active job config when inspecting solved ranges. Editing scenario makes it dirty; running a new scenario produces a separate result. Don't pair an old strategy with modified input.

UI needs: scenario controls, seat stacks/ranges, action-tree breadcrumbs + available actions, pot/contributions, 13x13 range matrix, hand details, training progress/cancel, result JSON download, scenario config import/export, clear model information. Errors inline. Export scenario can be entirely browser-local. CSV range export may be local from current-node strategy.

## Fixed native benchmarks

GET /api/meta adds research:{engine,max_samples,model,presets}. Select a returned config verbatim; only iterations (100–60,000,000) and seed can change. engine=hrc_v4_research selects the native implementation; benchmark is nine20bb, nine10bb, or hu10bb. Other fixed fields are checked, unknown engines fail 400. A preset imports only settings/topology for training.

Native nodes add native_id, street (0–3), street_name and buckets. Preflop hands remain keyed by label; postflop keys are 桶 N and basis=current_regret_policy. Relative EV values are in BB relative to action 0, not absolute self-play EV. Once training ends, preflop hands include reference:{frequencies,relative_ev_bb}. summary.comparison reports root uniform-combo conditional error and coverage only. Original strategies are first loaded after training. The node route reads a finished checkpoint lazily; no partial checkpoint is exposed during mutation. All raw proprietary resources remain outside WEB_ROOT. Native artifacts persist under .research-cache/runs; export JSON explicitly declares its scope.

## HRC ZIP interchange

- `POST /api/import` accepts binary `.hrcz` and `.plabz`; identify by ZIP members rather than filename. Limit: 1 GiB compressed and expanded. Duplicate/encrypted/unsafe paths, invalid indices and malformed shapes are rejected.
- `GET /api/jobs/{id}/hrcz` returns an HRC-compatible ZIP with `settings.json`, `state.json`, `gametree.dat`, `nodedata.dat`, `idx.dat`. Optional `?resources=1` includes local resources inside the native continuation extension. An unchanged original import returns its original archive bytes.
- Job capabilities add `can_export_hrcz` and `has_source_strategy`. A read-only source may save `.hrcz` while `can_resume=false`. Source scenarios use `engine=hrc_imported`; input geometry, equity settings and actual saved tree are immutable. Run controls and additional sampling targets can change.
- Source per-hand visits and original RNG/global sample history are unknown. `has_saved_policy=true` makes a saved policy visible even when `visits=null` or new visits are zero. `new_visits` and `summary.iterations_completed` count only samples since import. `summary.hrcz_import.source_saved_counter` is the original float32 update clock, not original global iterations. That clock remains in the native CFR state.
- Supported saved decision formats: 23/25/27/31/63, including compatible locks and frequency targets. Unknown profiles/formats, mixed per-street stores and unsupported subtree/model settings remain read-only; no silent replacement tree or abstraction is used. Independent native payoffs are checked against the source baseline before training.
- Our exported files can contain `prefloplab/checkpoint.plabz` plus a manifest binding all five core SHA-256 hashes. Only an unchanged matching extension restores native doubles/RNG/visits exactly. A HRC re-save uses normal source import when it removes or changes that extension. Standard HRC core data remains sufficient for HRC and for source strategy import.

Desktop validation: `reports/hrcz-real-program-roundtrip.json`; exported eight-player PKO 60M file was opened and saved by HRC, then re-imported. All 617,045 policy buckets, 164,380 observed EV buckets and 106,312 terminal values remained exactly equal. This validates file interoperability; it does not claim equivalence of original random streams or solver convergence.

## Native shared-policy parallel training

Native run config accepts `threads` (integer 1–32, API default 1). Resume also accepts a top-level `threads` override, including immutable imported scenarios. It changes the execution schedule, not the tree identity or utility. Each sample is counted once across workers; root/global counts are totals, not counts per worker. Summary includes `training_threads` and `parallel_mode` (`serial` or `async_shared`). Default new UI fields select four; users may select one for the existing serial update order.

Workers share synchronized strategy stores and immutable topology/abstractions. RNG, deal/rank state, terminal values, equity caches and FGS caches are private. Checkpoints are written only between completed batches. The optional `HRPAR001` trailer preserves all worker RNG states; v3 node offsets remain unchanged. `.plabz` and our `.hrcz` native extension preserve and validate it. Standard HRC core serialization still carries its original policy/EV formats, without claiming to preserve our random streams after an original-program re-save. Policy/store migration preserves the validated trailer. Resuming with the same worker count restores each stream; changing the count preserves the primary stream and initializes new extra streams. Parallel scheduling is nondeterministic, so checkpoint equality across repeated parallel runs is not a supported guarantee.

Parallel writers use a 64-byte-aligned `NodeMutex` with acquire/release synchronization, relaxed polling, CPU pause and periodic thread yield. Each node lock occupies its own 64-byte slot, included in the memory budget. For ordinary formats 23/25 without active locks or frequency constraints, supported GNU/Clang targets read regrets and the raw counter using relaxed, lock-free 64-bit atomic operations; the same fields are atomically written by the serialized writer. A strategy can contain cells observed at different update times. This is deliberate asynchronous sampling, not a coherent whole-node snapshot or a promise of identical parallel policies. Each worker has a private, budgeted exploration cache. Allocation refusal, unsupported compilers/targets, other formats and active constraints retain the locked route. Native MSVC currently uses that route. Control and condition-variable locks remain `std::mutex`. The node lock does not guarantee fairness or bounded waiting.

Immutable traversal metadata and writer-only scalar counters occupy separate cache lines in the node array. The current Win64 node size is 256 bytes with 64-byte alignment; actual `sizeof(Node)` is charged to the input memory budget. Ordinary two/three-action atomic reads preserve action order, zero/NaN/infinite handling and division semantics. A two-action finite positive total with one zero entry can return the other as exactly one without division. No reciprocal approximation or reduced floating-point precision is used.

Additional private caches and thread stacks are reserved against the process memory budget before allocating them. FGS state/sweep/work limits apply per worker, while the native byte budget is process-wide; FGS summary currently identifies worker-0 statistics explicitly. Cancellation and resource failures retain the most recent complete boundary checkpoint.

Native workers now claim independent blocks of at most 250 samples within control slices (normally 50ms). Completed blocks can immediately claim more work; workers quiesce before the main thread reads CI, saves, merges counters or captures RNG streams. A deadline requests a pause, not a hard real-time interruption: already claimed blocks finish, and their duration may extend a slice. Exact global sample budgets still apply. `parallel_scheduler` identifies `independent_blocks`, `synchronized_batches` or `serial`; `parallel_control_rounds` and `parallel_claimed_blocks` are invocation diagnostics. The old synchronized path remains available for controlled native CLI A/B runs. Scheduling changes parallel interleavings, not the game tree or checkpoint format.

Unraked ChipEV runs can independently precompute immutable terminal utility tables shared by workers. Existing per-deal and card-independent caches remain active. Table construction preserves sidepots, tied awards, uncalled returns, and integer remainders using the independent settlement arithmetic; no original HRC payoff is a training input. Required CI memory is reserved first. Optional tables use at most 64MiB and one quarter of the remaining configured budget; allocation/budget refusal retains online settlement. ICM, MTT, KO/PKO, rake and FGS retain their existing settlement path. Summary reports `terminal_tables`, `terminal_table_bytes`, `terminal_table_outcomes`, preparation seconds, actual `terminal_table_lookups`, and `terminal_settlements` (online cache misses), summed across workers. These are execution diagnostics and do not enter checkpoint identity.

After table publication, workers may allocate an optional compact per-terminal `(epoch, immutable payoff pointer)` cache. The owning table remains alive in each worker; no pointer or scratch cache is serialized. Total allocation is checked before any worker publishes its cache. Budget/allocation refusal retains the previous terminal path. Summary reports `terminal_pointer_cache` and `terminal_pointer_cache_bytes`, plus `unlocked_strategy_reads` and `unlocked_read_cache_bytes` for the independent strategy-read optimization. The existing `terminal_table_setup_seconds` includes this optional scratch setup.

Static abstract-card board rows use an immutable primitive open-addressed map; canonical keys, bucket IDs and compressed u16/u8 resource payloads are unchanged. The exact power-of-two key/value capacity and board input temporary are budgeted before loading. Two/three-seat static runs fill all seats from the same board row on its first use. Larger tables retain lazy per-seat filling; dynamic chance/range tables always keep their own per-actor mapping path.

For native CLI diagnostics, optional arguments 20 and 21 select terminal tables and the independent scheduler (each `0|1`, default `1`). To reach them, supply argument 19's explicit additional-sample budget as documented below. The Python/Web/API sample limits remain unchanged. New-header contents are included in the native build digest, so header changes produce a distinct executable without replacing an in-use Windows binary.

The explicit `max_memory_bytes` budget supports 1 MiB–8 GiB; its default remains 1 GiB. The limit permits allocation up to the configured amount and does not allocate that amount in advance. A 6 GiB explicit budget is used for the complete nine-player 40BB benchmark. Current node sizes, worker count, required CI snapshots and optional scratch allocations enter the reported `estimated_memory_bytes`; the older 4.07 GiB estimate predates the separated node layout and read/pointer caches. No tree reduction accompanies this resource limit.

## Native deep-tree optimizations

Native run config and top-level resume overrides accept `constant_scalar_shortcuts` (boolean, default `true`). It is an execution option and does not enter the game-tree identity. The native kernel enables it only for unraked ChipEV: a scalar continuation may return a known value when the target player cannot act anywhere in the subtree, cannot win any remaining pot, and has the same chip payoff at every leaf. All actions remain in the tree. The vector path and every target-player strategy update remain present. ICM, MTT, KO/PKO, rake and FGS automatically disable this shortcut, because another player's result may affect the target's utility.

Skipping redundant draws changes the RNG trajectory, so enabling/disabling this option does not preserve a fixed-seed checkpoint byte for byte. Its setting may change on resume without migrating the strategy stores; use `false` to retain the prior scalar traversal. Summary distinguishes `constant_scalar_shortcuts_requested` from the actual `constant_scalar_shortcuts`, and reports `constant_scalar_nodes` plus `constant_scalar_calls` (the latter covers only this invocation, summed across workers). Index `algorithm` gains `_constant_scalar` only when the shortcut is active. Binary checkpoint/node formats and standard HRC ZIP members are unchanged.

Native models also use cached bucket lookup, per-deal winner-mask caching, and full-key equity cache hits before repeated validation. Failed full-key comparisons still validate every miss, including unused seats. Final checkpoint saving reuses an identical periodic save when no further sample or CI change occurred. `checkpoint_writes` and `checkpoint_seconds` count successful saves during the invocation; `training_checkpoint_seconds` excludes saves before the training timer. These diagnostic times do not enter checkpoint identity.

Full automatic checkpoints use wall time rather than a fixed million-sample interval. After each save, the next interval is `clamp(20 × measured save seconds, 30, 300)` seconds, measured from completion of that save. This aims to keep periodic I/O below about 5% when the 300-second recovery cap is not binding. Checks occur only between complete batches; long traversals or CI work can delay them. Normal completion and graceful cancellation always save the latest complete state. A crash/forced process termination can lose work since the last completed checkpoint, normally up to the chosen interval plus an in-progress batch/write. FGS cancellation inside a traversal rolls back to the last safe checkpoint instead of serializing partial updates.

Non-FGS runs write one startup checkpoint after worker RNG setup; a worker-allocation failure still saves a valid untrained boundary. FGS retains its additional pre-baseline safety checkpoint. No-work runs with CI disabled reuse the startup save; CI initialization flushes stores and requires a final save even when no new samples are requested. Summary reports `checkpoint_policy:"adaptive_wall_time"` and the last scheduled `checkpoint_interval_seconds`. Scheduling changes no traversal, RNG operation, tree identity or binary checkpoint format; fixed-sample single-thread runs with CI disabled remain byte-identical. CI/time targets use wall time, and asynchronous worker order is nondeterministic, so those runs need not produce identical strategies.

Checkpoint serialization tracks byte offsets without per-node file-position queries and uses two 64 KiB stream buffers. Binary bytes, index offsets, numeric formatting and the existing temporary-file replacement procedure are unchanged. Buffers are temporary stack storage; no second copy of the strategy stores is allocated.

For controlled research runs only, native CLI argument 19 can explicitly set an additional-sample safety budget in `[1, 10^12]`. Without that argument, cumulative targets above one billion retain the original early rejection. With it, cumulative targets up to `10^12` are accepted, but `max(target - restored_samples, 0)` must fit the explicit budget before resets, output saving or worker startup. Stored counters, RNG state, CFR/CI math and checkpoint formats are unchanged. Python/Web/API limits remain one billion; they do not implicitly opt in. The 3-player CI10 benchmark uses a cumulative cap of three billion and an explicit additional budget of 2.99 billion after its own ten-million initialization. A cap exit still does not count as reaching CI10.

## Formal Run Sampling workflow

The green Run command opens the HRC-style sampling dialog rather than immediately submitting the draft. The default is `solver_mode:"v4"`, `sampling_scope:"entire_tree"`, `stopping_mode:"ci"`, `target_ci:10.0`; both reset options start unchecked. New Hand creates a `sampling_stage:"initialization"` job with 10,000,000 fixed samples, as observed in the original new-hand handler. Initialization is explicitly distinguished from the subsequent formal `sampling_stage:"calculation"` job; it does not claim the CI goal was reached. `meta.training.initialization_samples` exposes this default.

Native config and top-level resume overrides support:

- `stopping_mode`: `samples`, `ci`, or API-compatible `time`. Explicit modes select one completion criterion. CI mode enables tracking and defaults to 10; time requires `stop_after_seconds`. Use `hard_seconds` as a time cap, not as a second successful completion criterion.
- `iterations`: cumulative sample target in samples mode; cumulative safety cap in CI/time mode. Omitting it in CI/time mode uses 1,000,000,000. An explicit smaller cap remains binding. Reaching a cap is not reaching a CI target.
- `sampling_scope`: `entire_tree` or `selected_subtree`; `sampling_path`: child-edge indices from the stored tree root to the decision point. Entire Tree requires an empty path. Selected Subtree requires an initialized/saved hand, a nonterminal preflop decision and reachable frozen prefix ranges. Selecting an action in the table selects the decision before that action for this purpose, including all its available continuations.
- `sampling_stage`: `initialization` or `calculation`. Resume defaults to calculation instead of inheriting the initialization marker.
- Existing `solver_mode`, `threads`, `reset_regret`, `reset_average`, `target_ci`, `track_ci`, `stop_after_seconds`, `hard_seconds` and `max_memory_bytes` keep their documented ranges. The memory budget is available to all native application adapters.

Explicit mode switches clear a previous mode's completion target. Changing only CI tracking uses a runtime native option, preserving the historical input flag and checkpoint identity. Archive validation continues to enforce the saved input/hash plus every poker/model/store constraint; CI tracking can differ from that historical input flag. A formal v3/v4 change copies the checkpoint into the new job and changes only the algorithm header before continuing; original data is retained.

The dialog's fixed `Samples` field means additional samples for this invocation, defaulting to 50,000,000. The browser converts it to the cumulative API `iterations`; an initialized 10m hand plus a 50m request therefore submits 60m. The CI advanced safety cap remains cumulative. Selected Subtree uses frozen display-policy prefix ranges including folded players; only its descendants may update. It invalidates the mixed-history global root mean, exposing `root_mean_valid:false` and null root mean values through subsequent resumes and archives. Per-node action-relative EV remains available.

In the formal dialog, Reset Regret implies Reset Strategies: full reset applies both accumulator operations, whereas Reset Strategies alone retains regret/EV accumulators. Explicit native callers without a `stopping_mode` retain the historical independent-flag API. Resets apply once before sampling and only inside the selected scope.

Summary exposes the actual stop reason and `precision_target_reached` only for a formal CI-target stop. A finished fixed-sample or initialization job is never described as having met the precision goal. CI measures recent strategy drift, not a confidence interval or error percentage. Progress remains indeterminate when CI/history cannot support a meaningful estimate.

`GET /api/meta` adds `custom_native.preflop_presets` (id, label, preflop, sources) and `custom_native.scenario_presets` (id, label, description, config). They are bundled application data and do not require an installed HRC or a preset import. A preflop preset replaces only `tree_settings.preflop`; standalone scenarios provide a complete editable config. Local `.preflop.js` import accepts UTF-8 declarative JSON assignments up to 128 KiB, rejects executable code and unknown settings, and never evaluates JavaScript.

Custom scenes support optional integer `chip_scale` (1–100,000,000; default 10,000). Stacks/blinds/antes and rake caps must be exactly representable in these internal units; there is no silent rounding. GUI chip_scale=100 displays the supplied HRC chip amounts while preserving original internal long[] values and odd-chip behavior. External MTT stacks use scene units in config, internal units for training and GUI chips (internal/100) in HRC settings. FGS future blind amounts use the same configured precision. `.hrcz` projection metadata includes chip_scale, so rescaling requires a new settings projection rather than reusing stale source values.

Explicit native cumulative sample caps can be up to 1,000,000,000,000. The default CI/time safety cap remains 1,000,000,000. Above that default, the Python adapter supplies the native kernel's existing explicit additional-budget argument; uint64 checkpoint counters remain unchanged. A large cap is still a safety limit and is never a convergence claim.

With an explicit runtime CI override, resume also retains historical diagnostic `provenance` when every other portable native input is identical after preserving the historical CI flag. This handles independently rebuilt settings whose source JSON digest differs despite identical solver inputs. Any changed topology, terminal, equity, policy, store or unknown input field prevents this metadata substitution and remains subject to the native checkpoint identity check. Source checkpoints and caller inputs remain unchanged.

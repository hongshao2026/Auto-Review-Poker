日期：2026-11-04（Asia/Shanghai）。审查范围为 `preflop_lab/cards.py`、`preflop_lab/core.py` 的发牌概率、信息隔离、MCCFR 更新、筹码结算、ICM、加注规则与输入验证。审查者没有修改引擎实现，独立测试位于 `tests/test_independent_review.py`。

结论：本轮 17 项独立测试全部通过，完整独立文件运行耗时 0.49 秒。发现并修复了一处输入容器验证问题。未发现本轮覆盖范围内其他可复现的概率更新或结算错误。这不等于穷尽验证所有 NLHE 状态，也不构成与 HRC 精度相同的证据。

## 数学审查

- **联合发牌：**每个玩家先按组合权重独立取样，出现重牌时整组拒绝重抽。这样得到独立范围乘积在合法联合发牌上的条件分布；没有采用会改变早期座位边际概率的逐座位归一化替代。独立统计案例验证了一个明显存在 blocker 效应的精确边际。
- **私有信息：**信息集键为公共行动路径与行动者自己的手牌类别。对手私牌和公共牌样本只进入最终收益计算；没有发现用对手牌决定该玩家信息集的路径。169 类抽象对应输入支持的花色对称范围。
- **Regret：**更新者的动作展开枚举，对手按当前策略取样；counterfactual regret 使用各动作收益减策略期望，没有错误地再乘更新者的自身到达概率。
- **平均策略：**使用单独的、具有完整动作支持的轨迹采样。累计权重为自身到达概率除以公共轨迹采样概率；条件期望消掉公共采样概率。固定手牌类别下，稳定的发牌边际在归一化时抵消。这避免了多人场景直接套用无校正 opponent-node averaging 的问题。公开实现对这一问题的解释可见 [OpenSpiel external sampling](https://raw.githubusercontent.com/google-deepmind/open_spiel/master/open_spiel/python/algorithms/external_sampling_mccfr.py)。本项目没有复制该实现代码。
- **筹码与 ICM：**按投入层划分主池/边池，独占的未跟注层返还；弃牌贡献保留，平局分池。ICM 使用精确递归，另以完整名次排列作为独立 oracle 验证。同一手淘汰按起手筹码排序，起手筹码相同者平分相关名次奖金。

平均策略估计仍可能有很高方差。通过小博弈验证不能推出六人 NLHE 或 ICM 目标的一般 Nash 收敛保证。当前扑克产品没有计算 exploitability；不得将下述 Kuhn 指标移用到扑克结果界面。

## Kuhn poker：精确策略评估结果

测试适配器仅替换博弈规则、动作和收益；直接调用产品中的 `_traverse`、`_average_pass`、`InfoSet.strategy` 与平均策略累计实现。随机种子为 901114，共 12,000 次迭代。对最终平均策略枚举全部 6 种不同私牌发牌；对每位玩家枚举全部 64 种确定性信息集策略，得到精确 best response，而非通过额外对局抽样估计可利用度。

| 指标 | 结果 |
|---|---:|
| 玩家 0 平均策略收益 | -0.05564391319526 |
| 理论均衡收益 -1/18 | -0.05555555555556 |
| 均衡值绝对差 | 0.00008835763970 |
| 玩家 0 最佳回应收益 | -0.04661296300143 |
| 玩家 1 最佳回应收益 | 0.05980359471279 |
| NashConv：双方最佳回应改善之和 | 0.01319063171136 |
| 双玩家零和 convention：exploitability = NashConv / 2 | 0.00659531585568 |

单位为 Kuhn 的一单位底注。由于零和对局的当前双方收益之和为零，NashConv 可由双方 best-response 收益相加得到。本测试门槛是 NashConv < 0.06、策略值距离 -1/18 < 0.03；实测同时满足。测量记录位于 `analysis/kuhn-review-metrics.json`。完整 17 项套件通过后，仅单独运行 Kuhn 测量以记录所要求的数值，没有重复整个验证套件。

## 已处理问题与剩余边界

发现 `ResearchSolver` 在验证 payout 容器前调用 `len`，对 null、整数和布尔值抛出 TypeError。引擎作者已在长度检查前补上容器验证，上述 13–16 项提供回归覆盖。

审查还指出服务器曾把求解器 `resource_limit` 结果标成 completed。主代理已报告将其映射为失败并保留部分结果、显示中文原因，同时将浏览用树与训练实例隔离，避免浏览消耗训练预算。这两项属于集成层修复；本独立引擎测试文件未重新验证 HTTP/UI 状态映射。

资源预算会显式停止过大的树或信息集，不能把部分树称为完整收敛结果。高方差平均策略、稀有线路覆盖不足、有限下注尺寸、过牌到底 continuation、多人/ICM 一般收敛问题仍需明确呈现。未开展与 HRC 的受控数值对照，也没有检验全部七张牌组合的评估器实现。

复现独立测试：在项目根目录使用 `.venv\Scripts\python.exe -m pytest tests/test_independent_review.py -q`。

# 本地内核性能排查

后续状态：本报告记录合入前的实验；正式优化与较长运行验证见 `research/HRC-PERFORMANCE-OPTIMIZATION.md`。

2026-11-06，Windows，本机 i5-13600KF，14个物理核/20个逻辑处理器，系统物理内存31.84GiB。正式求解器及其编译参数未改动。实验只写入隔离目录 `.research-cache/performance-audit-20261106*`。

## 实测

页面通过本机 Python 服务启动本地 C++ 程序；训练循环为单线程。实验中进程平均使用约0.94–0.97个逻辑处理器，换算整机总CPU约5%。原生进程峰值常驻内存约354MiB（ChipEV）和386MiB（ICM/PKO），不包括浏览器、服务器和另开的HRC。

两组实验都使用八人15BB树、固定seed43，每次从零训练500,000样本，三次重复，轮换变体顺序，分别测试ChipEV与ICM/PKO。收益是相对同组基线的吞吐倍率。绝对耗时包含最终检查点输出。没有固定CPU亲和性/时钟，小幅差异可能是噪声，不能按一次结果外推所有场景。

| 实验 | ChipEV中位耗时 | PKO中位耗时 | 对照结论 |
|---|---:|---:|---|
| 第一组：当前内核 | 2.997秒 | 5.079秒 | 基线 |
| 第一组：`-march=native` | 3.017秒 | 5.197秒 | 没有稳定收益 |
| 第一组：固定终局缓存 | 2.896秒 | 4.638秒 | PKO吞吐+9.5%，时间少8.7% |
| 第二组：当前内核 | 3.098秒 | 5.413秒 | 独立基线 |
| 第二组：按需计算牌力 | 2.996秒 | 5.342秒 | 单独效果小且波动，不能确认稳定收益 |
| 第二组：两种优化组合 | 3.057秒 | 4.495秒 | PKO吞吐+20.4%，ChipEV仅+1.4% |

36次短跑的同模型检查点SHA-256全部相同，覆盖遗憾、平均策略、RNG、根收益和访问计数。这些比较没有调用原版HRC或加载原版策略。另用每个实验程序运行内置数值探针，结果记录在 `reports/hrc-performance-audit.json`。这些是有限预算下的等价性与速度证据，不是均衡收敛证据，也不是6000万次全程验证。

固定终局缓存只缓存所有争夺池均只有一个合资格赢家、因此不依赖本手牌面的结算结果。当前代码只在同一随机发牌内缓存；下一手会重算同一固定结果。实验把这种结果跨手复用，避开重复派奖、货币终局校验与权益缓存查询。明确排除抽水和FGS，正式接入时还需要这些模式及重置/续跑回归。

按需牌力计算把第一次摊牌就评估全部座位，改为只算当前pot.eligible需要的座位；同一发牌内用掩码复用已算结果。它不改变发牌和随机调用，但探索分支可能最终仍需要大多数玩家，所以单独收益不明显。组合数据不能据此推导两个独立加速比例可相加。

## 进一步可直接核查的点

1. **桶表内存表示。** `native/hrc_cards.hpp` 的 turn/river profile 都只有256桶，编号0..255，内存却与flop统一使用uint16。内部改为uint8可准确表示，相关两张表从327,770,950字节降至163,885,475字节，节省约156.29MiB；flop1024桶仍保留uint16。磁盘资源格式和SHA验证可以不变。需要测实际访存收益，不能仅凭内存减半承诺训练翻倍。
2. **计数对应的数学量。** `Node.update` 每次算floor(sqrt(counter+1))，`Engine.sample` 每次算探索概率1/sqrt(counter+10000)。翻前缓存计数在多次访问中可能不变，可按实际stored counter缓存数学结果，维持相同计算精度和RNG调用顺序；reset/resume/CI flush必须使缓存正确更新。尚未测量整机收益。
3. **约束节点的临时分配。** `BucketLocks.compose`、`FrequencyStore.strategy` 在训练热路径返回多个小vector，而每节点最多16个行动。调用方固定缓冲区可消除这些分配，且不改数值操作顺序。这主要影响有锁定或频率约束的场景，当前无约束短跑不能量化其收益。
4. **多核并行。** 现有训练只使用一个逻辑处理器，硬件还有较大空间。但scalar/vector递归会即时修改共享遗憾与平均策略，且共用随机流，不能简单为循环加线程再声称结果完全相同。独立场景并行较直接；单场景并行需要独立设计和统计验证，特别是ICM/PKO与锁定模式。20逻辑线程不等于20倍加速。

优先顺序：先把固定终局缓存作为小补丁进行全模式回归，再测试桶表内部压缩和计数数学缓存；多线程单独作为后续内核功能。`-O3` 已启用，本轮不支持“再加编译参数就明显变快”的判断。

可复现命令见 `scripts/audit-hrc-performance.py --help`，原始逐轮数据、命令、峰值常驻内存和检查点哈希保留在汇总报告及两个隔离实验目录。
